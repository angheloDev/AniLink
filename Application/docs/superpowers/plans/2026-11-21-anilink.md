# AniLink Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build AniLink, a local-only Android prototype marketplace for Zamboanga City farmers and buyers (listings, live chat, structured offers, orders, facades), with a local Node/MongoDB server.

**Architecture:** An Expo (React Native, Expo Router, TypeScript) app talks to a local Express + Socket.IO + Mongoose server over the LAN. State on the device (token, theme, language, server URL) lives in AsyncStorage. Server logic that can break a demo (offer state machine, order transitions, price-guide badge, alert matching) is pure functions with unit tests; screens are verified by running them on the emulator.

**Tech Stack:** Expo (latest SDK via `create-expo-app@latest`), expo-router, TypeScript, react-native-keyboard-controller, expo-notifications, expo-image-picker, react-native-webview + bundled Leaflet, i18next, @tanstack/react-query, zustand, @expo-google-fonts/poppins, Express, Socket.IO, Mongoose, multer, bcryptjs, jsonwebtoken, vitest + supertest, jest-expo.

**Spec:** `Application/docs/superpowers/specs/2026-11-21-anilink-design.md`

## Global Constraints

- Layout: `Application/mobile` (Expo app), `Application/server` (API), `Application/logos` (existing, do not edit), `Application/docs`.
- Server: binds `0.0.0.0:4000`; DB `mongodb://127.0.0.1:27017`, database `anilink` (tests use `anilink_test`); the MongoDB Windows service is already running; no mongod install needed.
- Mobile reads server URL from `EXPO_PUBLIC_API_URL`, overridable in-app (AsyncStorage key `anilink.serverUrl`).
- Font: Poppins 400/500/600/700 everywhere. Logos: `logos/app-loading-logo.png` (native splash + animated splash), `logos/homescreen-logo.png` (app icon, loaders, headers).
- Dark theme (default) tokens: bg `#1F1E1B`, surface `#272622`, card `#161614`, border `#34322D`, primary `#1E4A3D`, primaryText `#C9E8D6`, headline `#BEE3CF`, eyebrow `#6FBF8E`, accent `#E8834A`, sun `#F0C04B`, mustard `#A8873A`, text `#ECE8E0`, muted `#9E998F`, sectionGreen `#1A3F36`, deepGreen `#0F2E28`; tints tomato `#4A2E28`, banana `#3D2E14`, leafy `#2E3D2E`, mango `#3D3608`.
- Light theme tokens: bg `#F6F3EC`, surface `#FFFFFF`, primary `#1E5A45`, headline `#1B4D3E`, accent `#D9702F`, text `#1F1E1B`, muted `#6B675E`; remaining tokens (card, border, primaryText, eyebrow, sun, mustard, sectionGreen, deepGreen, tints) are lightened counterparts of the dark values. Theme mode: system | dark | light, persisted.
- Languages: English default, Tagalog (`tl`) toggle, persisted; every user-visible string goes through i18next.
- Roles: `farmer` | `buyer`, chosen at onboarding, switchable in Profile.
- Units: `kg | piece | tali | sack | dozen`. Categories: `vegetables | fruits | leafy | rootcrops | grains | crafts | others`.
- Offer statuses: `pending | accepted | declined | countered | superseded`. Order statuses: `pending_payment → paid → preparing → ready_for_pickup | out_for_delivery → completed`, plus `cancelled`.
- No Firebase. Notifications: Android channel `anilink` (high importance); background delivery is enough, fully-swiped-away delivery is out of scope.
- Payment facade uses generic wallet styling only; no real GCash/Maya/bank logos.
- Map: Leaflet JS/CSS bundled in the app; OSM tiles when online, bundled Zamboanga base image when offline.
- Price-guide screens are labeled "Sample data".
- Android first (iOS untested). Phone runs a release APK; emulator may run debug.
- Each task ends with a commit; commit messages end with the attribution line required by the session.

## Review Focus

1. Duplicate registration with different email casing (`A@x.com` vs `a@x.com`) → second returns 409; login is case-insensitive. (Task 2)
2. Offer actions by the wrong user, or on an already-resolved/superseded offer → rejected (403/409), never double-creating an order. (Task 5)
3. Offer quantity above stock, or accepting after stock dropped → rejected; stock decremented exactly once per order. (Tasks 5, 6)
4. Server unreachable or wrong IP at app start → splash ends within ~6 s, offline banner + editable server address; no infinite spinner. (Tasks 13, 14)
5. Keyboard covering the focused field on small screens, long chat histories, empty states (no listings / chats / notifications), and long Tagalog text with `ñ`/emoji in messages. (Tasks 12, 21)
